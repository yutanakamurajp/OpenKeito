# 論文の材料: 図表を再現するスクリプトと、主張と根拠の整理

投稿先はまだ決まっていない。ここには、どの投稿先にも使える材料だけを置く。原稿は置かない。

- 図表は 1 つのコマンドで作り直せる (下の「使い方」)。
- 比べる相手は、解析解、手計算、公開された文献の式、別に積分した同じ方程式に限る。ほかのシミュレータとの比較は入れていない。
- 下の数字は、2026-11-22 に `python paper/make.py` が出した値である (OpenKeito 0.6.0、モデル形式 0.5、Windows 11、
  Python 3.11、numpy 2.4.6、pandapower 3.5.6、pypowsybl 1.16.1、matplotlib 3.11.2)。M9 Stage 4 で追加した
  `controls_v07`・`wecc_ibr` の数字は 2026-11-24 に OpenKeito 0.11.0、モデル形式 0.7、Python 3.12 で出した値、M10 段 2 で追加した
  `expression_control`・`ieee39_diagram` の数字は 2026-11-25 に OpenKeito 0.11.0、モデル形式 0.8、Python 3.12 で出した値、M10 段 4 で追加した
  `ai_control` の数字は 2026-11-25 に OpenKeito 0.13.0、モデル形式 0.8、Python 3.11 で出した値、M11 段 1 で追加した
  `pwm_accuracy`・`thyristor_rectifier` の数字は 2026-11-26 に OpenKeito 0.13.0 (M11 段 1 の作業中の版)、モデル形式 0.9、
  Python 3.11 で出した値 (`pwm_accuracy` の 25 µs は 2026-11-27 に 0.14.0 の上で刻みの中の頂点を見るように直した版で出し直した)、M11 段 2 で追加した `grid_tests` の数字は 2026-11-27 に OpenKeito 0.14.0 (M11 段 2 の作業中の版)、
  モデル形式 0.5 (例の設備)、Python 3.11 で出した値である。計算時間だけは
  `docs/performance.md` に記録済みの値で、このスクリプトは測り直していない。

## 使い方

```sh
pip install ".[paper,pandapower,powsybl]"     # matplotlib と、変換に使う 2 つ
python paper/make.py                          # 全部。出力は paper/out (Git に入れない)
python paper/make.py --only buck_switching    # 1 つだけ (--only は繰り返せる)
python paper/make.py --out <dir>              # 出力先を替える
python paper/make.py --list                   # 項目の一覧
python paper/make.py --quick                  # 小さい設定 (テスト用。数字は本番と違う)
python paper/make.py --measure                # 計算時間をこの機械でも測る
```

- 項目ごとに、数値の CSV (図の元データ)、図 (PDF と PNG)、表 (`.tex` と `.md`) を書く。項目の主な数字は
  `numbers.json` にまとまる。
- 乱数も時刻も使わない。同じ入力からは同じファイルが出る (全部を 2 回作り、87 ファイルがバイト単位で同じことを確かめた。
  PDF と PNG も日付を書かないので同じになる)。潮流の反復の結果は pandapower・pypowsybl の版で最後の桁が変わりうる。
- 計算時間は機械に依存するので、ほかと分けてある。既定では `paper/data/*_recorded.csv` (`docs/performance.md` の表を
  写したもの) から図を作る。`--measure` を付けたときだけこの機械で測り、`*_measured.csv` に書く。測るときは 1 つの
  速いコアに固定する (`figures/performance.py` の冒頭に手順)。
- 体裁は `style.py` の 1 か所で替える (フォント、文字の大きさ、1 段・2 段の幅、線の太さ、色)。系列は色と、線種・
  マーカーの両方で区別してあり、白黒でも読める。色は 4 色で、隣り合う組が色覚の型 (1 型・2 型・3 型) で区別できる
  ことを検査した組。黒は参照 (解析解など) だけに使う。ラベルは英語。
- テスト: `python/tests/test_paper_figures.py` が `--quick` で最後まで走らせ、CSV の主な値の範囲を確かめる
  (matplotlib が無ければ skip)。

構成: `make.py` (入口)、`style.py` (体裁)、`lib.py` (CSV・表・実行・フェーザ・行列指数関数)、`figures/<項目>.py`
(項目ごと。冒頭のコメントに回路、参照の式、文献)、`data/` (記録済みの計算時間)。

## 主張と根拠

主張は、根拠のある範囲で書く。「テスト」は `crates/openkeito-core/tests/` と `python/tests/`。

## 新規性として言えそうなこと、言えないこと

言えそうなこと (どれも「組み合わせ」と「検証を付けて公開すること」であり、個々の方法の新しさではない):

- EMT の入力を、人と AI エージェントが同じテキストで扱えるように作ったこと: 単位を名前に入れた JSON、JSON Schema、
  部品の一覧、コード・場所・hint を持つ診断、実行ごとの summary、MCP サーバー (主張 12)。
- 潮流・OPF・CGMES の既存の OSS の結果から、変換の約束を明示して EMT の定常状態を作り、潮流解との差を数字で示した
  こと (主張 9)。差の出どころ (潮流の収束判定、刻みの誤差) を分けて示せる。
- 計画値の時間断面と推移を、検証付きで一括実行する流れ (主張 10)。並列と逐次のビット単位の一致を保証している。
- 2S-DIRK の上で、切り替え時刻で刻みを分ける方式を実装し、スイッチングをまたぐ 2 次の精度を厳密解で示したこと
  (主張 3)。
- 部品ごとに閉じた解と比べるテストを持ち、許容誤差の根拠をテストに書いていること (主張 1〜8)。図表はその再現。

言えないこと:

- 個々の数値解法の新規性。2S-DIRK (Noda ほか 2009)、台形則と数値振動 (Dommel 1969、Marti・Lin 1989)、分布定数線路
  (Dommel 1969)、補間・刻みの分割の考え方 (Kuffel ほか 1997、Strunz 2004)、線路での分割と並列化 (Falcão ほか 1993、
  Marti・Linares 1994)、同期機の扱い (Wang・Jatskevich 2006 ほか) は既知。
- 「OSS で初めての EMT」「最も速い」「ほかのツールより正確」。ほかの EMT ツールとの比較は、ここには 1 つも無い。
  既存の OSS の EMT (DPsim など) の機能と精度は調べていないので、位置づけを書く前に調査が要る。
- 実測や実系統での妥当性。比べた相手は解析解、手計算、同じ方程式の別の積分だけ。
- 大規模系統での実用性。確かめたのは 118 母線 (変換) と、輪の 1000 母線 (計算時間) まで。
- 計算時間の一般性。1 台の機械で測った値で、ほかの作業が動いている間の測定はばらつく。
- AI エージェントにとっての使いやすさの定量的な評価。診断の例と道具立ては示せるが、エージェントが課題を解けた割合
  などの測定はしていない。

## 既存の OSS との位置づけ

| CIM/CGMES の読み込み | PowSyBl (pypowsybl、OpenLoadFlow) | IIDM の等価回路をそのまま組み、潮流が残した不つり合いを明示して持たせる | `power_flow_start` (MicroGrid BE・NL) |

| OSS の EMT | DPsim (参考) | 比べていない | — |

PyPSA との連携は未実装 (計画値ファイルで受ける設計だけ)。上の OSS の機能についての記述は `plan.md` によるもので、
載せる前にそれぞれの現行の版の文書で確かめる。

## 今の制約 (`plan.md` 8 章)

- スイッチング時刻の既定は格子点 (`interpolated` を指定すると刻みの中)。ダイオードと制御スイッチは 2 値抵抗
  (既定 1 mΩ・1 MΩ)。`diode_bridge` の参照には、この導通抵抗を入れてある (理想ダイオードの角度との差は 6.3e-4 rad)。
- 変圧器の飽和はヒステリシスと残留磁束なし、三脚鉄心の零相なし。線路は π 形と定数パラメータの Bergeron で、周波数依存なし。
- 同期機は磁気飽和なし。変換器は平均値モデルで、直流側は一定電圧。
- 制御と回路の間は 1 刻み遅れ (`converter_response` の 1 次の誤差の原因)。
- 2S-DIRK で、電源が電圧を決めるコンデンサの電流は 1 次の精度。
- 図表に入れていない部品: 非線形素子 (避雷器、飽和)、変圧器の結線、周波数スキャン、制御ブロック、PLL、6 パルス整流器、
  推移の 3 時刻以上の連結。どれもテストはある (`nonlinear.rs`、`three_phase.rs`、`controls.rs`、`switching.rs`)。
  要るなら項目を足す。

## 載せる前に確かめること

- 文献の章・節・表の番号を原典で確かめる (書誌は確認済み)。図表のスクリプトのコメントが挙げる Kundur、EMTP Theory
  Book、Yazdani・Iravani、Anderson、Grainger・Stevenson の章も同じ。
- 計算時間を、ほかの作業が動いていない機械で取り直す (`--measure`、コアを固定)。今回の作業中は、同じ PC でほかの
  作業が動いていた。`--quick --measure` での試しでは、輪 10・30 母線が記録の 1.06〜1.17 倍だった。wasm の比は
  このスクリプトでは測れない (Node と、ビルドした wasm が要る)。
- 並列の処理量 (1 秒あたりのケース数) は機械に依存するので、表には入れていない。`--measure` で
  `schedule_runs_measured.csv` に出る (この PC の試しでは、24 断面で 1 スレッド 180 件/s、8 スレッド 1135 件/s。
  変換の時間は含まない)。
- 依存の版を固定して記録する (今回の版は冒頭。`pip freeze` を投稿時の付録に付ける)。潮流の最後の桁は版で変わりうる。
- IEEE 118 (PowSyBl) の波形の角度の差は、負コンダクタンスを持つシャントの変換で容量性の無効電力分を定インピーダンス (コンデンサ) として残し負の有効電力分だけを電流源にしたことで、2.4e-2° (1 次) から 4.0e-3° (2 次、25 µs で 1.0e-3°。残りは母線 VL68 の非対称 π 形線路による 37 Gvar の電流源) に縮まった。
- 投稿先が決まったら、`style.py` の幅・フォント・文字の大きさを合わせ、図の面の組み方を見直す。
- ほかの EMT ツール (OSS を含む) との比較や関連研究の調査は、ここには無い。位置づけを書く前に行う。
- 商標・公開の手続き・著作権の表記 (`plan.md` 9 章) は、この材料の外で決まる。
